# Design Document: Firebase Firestore Real-Time Sync & Annual Audit Government Report Engine

- **Project**: ระบบบริหารงานพัสดุและครุภัณฑ์ โรงพยาบาลหนองจิก (Nongchik Hospital Asset Management)
- **Date**: 2026-11-11
- **Status**: Draft (Awaiting Builder Check & Approval)

---

## 1. Intent & The Why

### Background
โรงพยาบาลหนองจิกมีครุภัณฑ์กระจายอยู่ตามแผนกและตึกต่างๆ กว่า 34 แผนก ปัจจุบันแอปพลิเคชันเป็น Single Page Application (SPA) ที่จัดเก็บข้อมูลบน `localStorage` ของอุปกรณ์เครื่องนั้นๆ ทำให้:
1. ข้อมูลไม่เชื่อมโยงกันระหว่างแผนก เมื่อแผนกหนึ่งบันทึกแจ้งซ่อม โอนย้าย หรือแก้ไขสถานะ แผนกอื่นจะไม่เห็นข้อมูล
2. ในช่วงการตรวจนับพัสดุประจำปี คณะกรรมการตรวจสอบหลายคนไม่สามารถแยกย้ายกันไปสแกนตรวจนับตามตึก/วอร์ดพร้อมกันได้
3. การสรุปรายงานผลการตรวจนับพัสดุประจำปีตามระเบียบกระทรวงการคลังว่าด้วยการจัดซื้อจัดจ้างและการบริหารพัสดุภาครัฐ พ.ศ. 2560 ข้อ 213 ต้องทำด้วยตนเองนอกระบบ เสียเวลาและอาจคลาดเคลื่อน

### Why Now
การเชื่อมต่อ Firebase Firestore จะทำให้ระบบกลายเป็นระบบ Real-time Multi-user ทันทีโดยไม่ต้องตั้งเซิร์ฟเวอร์ และการเพิ่มเครื่องมือสร้างแบบรายงานราชการจะช่วยให้คณะกรรมการตรวจนับสามารถพิมพ์รายงานสรุปผลพร้อมบัญชีครุภัณฑ์ที่ชำรุด/สูญไปเสนอผู้อำนวยการโรงพยาบาลได้ในคลิกเดียว

## 2. Goals, Non-Goals & Anti-Goals

### Goals
- **Real-time Synchronization**: ซิงค์ข้อมูลครุภัณฑ์ (`assets`), ประวัติยืม-คืน (`transfers`), ใบแจ้งซ่อม (`tickets`), และผลการตรวจนับประจำปี (`annual_audits`) ผ่าน Firebase Firestore
- **Multi-user Concurrent Audit**: คณะกรรมการหรือเจ้าหน้าที่หลายคนสามารถเปิดระบบในสมาร์ตโฟนหรือคอมพิวเตอร์เพื่อสแกน QR ตรวจนับพร้อมกันแบบ Real-time โดยสถานะจะอัปเดตบนหน้าจอของทุกคนทันที
- **One-Click Initial Data Migration / Seeding**: มีระบบตรวจสอบและนำเข้าข้อมูลครุภัณฑ์ที่มีอยู่เดิม (`EMBEDDED_ASSETS`) ขึ้นสู่ Firestore ในคลิกเดียว
- **Offline Resilience**: รองรับการใช้งานแบบ Offline-first ผ่าน IndexedDB Cache หากสัญญาณอินเทอร์เน็ตหลุดในจุดอับสัญญาณ และส่งข้อมูลขึ้นคลาวด์อัตโนมัติเมื่อออนไลน์
- **Government Compliance Annual Audit Report**:
  - รองรับการกรอกข้อมูลคำสั่งแต่งตั้งและรายชื่อคณะกรรมการตรวจสอบพัสดุประจำปี
  - จำแนกสถานะตามระเบียบพัสดุภาครัฐ (ใช้งานปกติ, ชำรุดซ่อมแซมได้, ชำรุด/เสื่อมสภาพไม่คุ้มค่าซ่อมเพื่อขอจำหน่าย, สูญไป/หาไม่พบ)
  - พิมพ์รายงานผลการตรวจสอบพัสดุประจำปีรูปแบบ A4 มาตรฐานราชการ (Print / Save as PDF) พร้อมส่วนลงนามคณะกรรมการ
  - ส่งออกข้อมูลเป็นไฟล์ Excel (.xlsx) ที่จัดรูปแบบคอลัมน์และสรุปยอดถูกต้อง

### Non-Goals
- ไม่ทำระบบจัดการสิทธิ์ระดับองค์กรขั้นสูง (เช่น LDAP / Active Directory ของกระทรวงฯ) ในระยะนี้ ให้ใช้ Firebase Config + รหัสเจ้าหน้าที่/PDPA Profile ที่ระบุชื่อและแผนก
- ไม่เปลี่ยนโครงสร้างสถาปัตยกรรมไปเป็น Node.js/Backend Server เพื่อรักษาคุณสมบัติ Zero-Build SPA ที่เปิดใช้งานได้สะดวก

### Anti-Goals
- ห้ามทำลายหรือลบความสามารถในการทำงานแบบ Local/Offline เดิม หากไม่ได้กรอก Firebase Config ระบบต้อง Fallback มาทำงานบน `localStorage` ได้อย่างราบรื่น 100%
- ห้ามพึ่งพาไลบรารีที่คิดค่าบริการ หรือต้องรันคำสั่ง Build/Compile ซับซ้อน

## 3. Constraints
- **Platform**: Client-side Single Page Application (HTML5, Vanilla JS, Tailwind CSS CDN) รันบนเบราว์เซอร์มาตรฐาน (Chrome, Edge, Safari, Firefox บน PC และ Mobile)
- **Zero-Build Requirement**: ต้องสามารถเปิดไฟล์ `index.html` ทำงานได้ทันที หรือรันผ่าน static web server
- **Regulatory Compliance**: โครงสร้างรายงานต้องสอดคล้องกับระเบียบกระทรวงการคลังว่าด้วยการจัดซื้อจัดจ้างและการบริหารพัสดุภาครัฐ พ.ศ. 2560 ข้อ 213

## 4. Architectural Approaches

### Approaches Considered:
1. **Approach 1: Firebase Web SDK (Client-Side Realtime) + Client-side Government Report Engine (SELECTED)**
   - โหลด Firebase SDK v10 (compat/modular ผ่าน CDN)
   - ใช้ Firestore `onSnapshot` สำหรับ real-time listener
   - ใช้ SheetJS (xlsx CDN) สำหรับส่งออก Excel และ CSS Print Template สำหรับเอกสาร A4
   - *เหตุผลที่เลือก*: ตรงความต้องการที่สุด ไม่เพิ่มภาระค่าใช้จ่ายและเซิร์ฟเวอร์ ติดตั้งง่าย
2. **Approach 2: Firebase Cloud Functions & Server-side PDF (Puppeteer)**
   - *เหตุผลที่ไม่เลือก*: ต้องเปิดแพ็กเกจ Blaze (เสียค่าบริการ), ต้องการ Node.js backend
3. **Approach 3: Google Sheets API / Google Apps Script (GAS)**
   - *เหตุผลที่ไม่เลือก*: ไม่รองรับ Real-time WebSockets/Listener แบบ Native, มีข้อจำกัดเรื่อง Quota และ Latency ขณะสแกนหลายคนพร้อมกัน

## 5. Detailed Technical Specifications

### 5.0 Builder Review Resolutions & Governance Rules (Settled Calls)
1. **การนับยอดครุภัณฑ์ (Denominator)**:
   - กรองเฉพาะครุภัณฑ์ที่ยังมีสถานะใช้งาน/คงอยู่ (`status !== 'จำหน่ายแล้ว/ยกเลิกการใช้'`) มาเป็นฐานในการตรวจนับประจำปี ครุภัณฑ์ที่จำหน่ายแล้วในปีก่อนจะไม่ถูกนำมาคิดในยอดคงเหลือและไม่ถูกตีเป็นของสูญหาย
2. **การจัดการสถานะ "ยังไม่ได้ตรวจนับ" vs "สูญไป/หาไม่พบ"**:
   - ในระหว่างที่รอบการตรวจนับยังเปิดอยู่ (`in_progress`) รายการที่ยังไม่ถูกสแกนจะมีสถานะเป็น `pending` (ยังไม่ได้ตรวจนับ)
   - จะไม่ตีขลุมว่าของที่ยังไม่ได้สแกนคือ "สูญไป" โดยอัตโนมัติ เพื่อป้องกันการรายงานเท็จระหว่างรอบตรวจนับ
   - มีหน้าจอ **กระทบยอด (Reconciliation Panel)** ให้กรรมการตรวจสอบรายชื่อของที่ยังไม่ได้สแกนแยกตามแผนก และสามารถกดระบุเป็น "สูญไป/หาไม่พบ" พร้อมบันทึกข้อสังเกตได้
3. **การจัดการรอบการตรวจนับ (Audit Round Lifecycle)**:
   - มีระบบสร้างรอบตรวจนับตามปีงบประมาณ (เช่น `audit_2569`) พร้อมระบุเลขที่คำสั่งและรายชื่อกรรมการ
   - เครื่องของเจ้าหน้าที่ทุกคนจะเชื่อมต่อไปยังรอบที่เปิดใช้งานอยู่ (`active_round`) โดยอัตโนมัติ
   - เมื่อตรวจนับเสร็จสิ้นและเสนอผู้บริหารลงนามแล้ว จะมีปุ่ม **"ปิดรอบการตรวจนับ (Finalize & Lock)"** เพื่อล็อกข้อมูลเป็น Read-only เก็บเป็นประวัติศาสตร์
4. **การทับซ้อนของการสแกน (Multi-user Concurrency)**:
   - ใช้หลักการ Last-Write-Wins โดยบันทึก `auditedAt` และ `auditorName` ของผู้สแกนคนล่าสุดไว้เสมอ

5. **พฤติกรรมการสแกนหน้างาน (Scanner UX - User Decision: 1 ก)**:
   - ใช้ระบบ **Fast Continuous Scan**: สแกนปุ๊บ ระบบบันทึกเป็น "ใช้งานปกติ" ให้อัตโนมัติทันที พร้อมเสียงตอบรับ (Beep audio feedback) เพื่อให้เจ้าหน้าที่เดินสแกนครุภัณฑ์ในตึก/วอร์ดได้อย่างรวดเร็วต่อเนื่อง
   - หากครุภัณฑ์ชิ้นใดชำรุด เสื่อมสภาพ หรือมีข้อสังเกต เจ้าหน้าที่สามารถแตะรายการเพื่อเปิดหน้าต่างเปลี่ยนสภาพเป็น "ชำรุดซ่อมแซมได้" หรือ "ชำรุด/เสื่อมสภาพไม่คุ้มค่าซ่อม" พร้อมพิมพ์บันทึกข้อสังเกตได้ทันที
6. **การปรับปรุงสถานะบัญชีหลัก (Master Ledger Sync - User Decision: 2 ก)**:
   - ข้อมูลการตรวจนับจะถูกบันทึกแยกไว้ในเอกสารของรอบการตรวจนับ (`annual_audits`) โดยไม่แก้สถานะบัญชีหลักทันที เพื่อรักษาหลักธรรมาภิบาลและความถูกต้องของข้อมูลระหว่างรอบตรวจนับ
   - เมื่อคณะกรรมการตรวจสอบครบถ้วนและผู้อำนวยการโรงพยาบาลลงนามอนุมัติรายงานแล้ว จะมีปุ่ม **"อนุมัติและปรับปรุงสถานะบัญชีครุภัณฑ์หลัก (Apply to Master Ledger)"** ในหน้าสรุปผล เพื่ออัปเดตสถานะใน `assets` อย่างเป็นทางการในคราวเดียว

### 5.2 Real-time Sync & State Architecture
- สร้าง `FirebaseBridge` module จัดการ:
  1. `initFirebase(config)`: ตรวจสอบและเริ่มต้น Firebase App & Firestore พร้อมเปิด IndexedDB Persistence
  2. `bindListeners()`: ผูก `onSnapshot` สำหรับ assets, transfers, tickets, และ annual_audits
  3. `syncFallback`: หากยังไม่เชื่อมต่อ Firebase ให้แอปพลิเคชันทำงานผ่าน `localStorage` โดยไม่มีข้อผิดพลาด (Graceful Degrade)
  4. แสดงสถานะการเชื่อมต่อมุมบนขวา (Status Badge: 🟢 เชื่อมต่อคลาวด์แล้ว / 🟡 ออฟไลน์ (แคช) / ⚪ Local Storage)
  5. เครื่องมือ Seeding: ตรวจสอบจำนวน documents ใน Firestore หากเป็น 0 ให้แสดงปุ่ม "นำเข้าข้อมูลเริ่มต้น 600+ รายการขึ้น Cloud"

### 5.3 Annual Audit & Government Compliance Reporting Engine

#### 1. สภาพครุภัณฑ์ตามระเบียบพัสดุภาครัฐ (4 หมวด):
- **สภาพปกติ (normal)**: ครบถ้วน ใช้งานได้ปกติ
- **ชำรุดซ่อมแซมได้ (damaged_repairable)**: ชำรุดแต่คุ้มค่าในการส่งซ่อม
- **ชำรุด/เสื่อมสภาพไม่คุ้มค่าซ่อม (deteriorated_unusable)**: เสนอขอจำหน่ายออกจากบัญชี
- **สูญไป/หาไม่พบ (lost)**: ไม่อยู่ในแผนกและไม่พบประวัติโอนย้าย เสนอดำเนินการสืบหาหรือจำหน่าย

#### 2. ส่วนประกอบรายงานผลการตรวจสอบพัสดุประจำปี (แบบฟอร์มทางการ):
- **ส่วนหัว**: บันทึกข้อความ / รายงานผลการตรวจสอบพัสดุประจำปีงบประมาณ พ.ศ. ....
- **คำสั่งแต่งตั้ง**: อ้างอิงเลขที่คำสั่งและวันที่ลงนาม
- **สรุปผลการตรวจสอบ**:
  - จำนวนครุภัณฑ์ทั้งหมด และมูลค่ารวม
  - สรุปแยก 4 สถานะ: จำนวนรายการ, คิดเป็นร้อยละ, และมูลค่า
- **บัญชีรายการครุภัณฑ์ที่ชำรุด เสื่อมสภาพ หรือสูญไป**:
  - ตารางระบุ: ลำดับ, เลขครุภัณฑ์, รายการ, วันที่ได้มา, ราคาจัดซื้อ, แผนก, สภาพความชำรุด, ความเห็น/ข้อเสนอแนะคณะกรรมการ
- **ส่วนลงนาม**: ลายมือชื่อประธานกรรมการ, กรรมการ, และกรรมการและเลขานุการ

#### 3. ช่องทางการส่งออกเอกสาร:
- **Print / PDF A4**: แสดงหน้าต่างพรีวิวรายงานจัดหน้ามาตรฐาน พร้อมปุ่มกดพิมพ์ (เบราว์เซอร์จะ Render หน้ากระดาษ A4 สวยงาม สามารถบันทึกเป็น PDF ได้ทันที)
- **Excel (.xlsx)**: ดาวน์โหลดไฟล์ Excel พร้อมตารางสรุปและชีตแยกรายการชำรุด/สูญไป จัดความกว้างคอลัมน์อัตโนมัติ
